==========================================================
  devref  --  UPDATES
  Changes from v2.0 → v2.1
==========================================================


----------------------------------------------------------
  FILE STRUCTURE  (changed)
----------------------------------------------------------

v2.0 layout:
  devref/
  └── ref/
      ├── tools.json      (all tools in one file)
      ├── snippets.json   (all snippets in one file)
      └── meta.json       (settings + recent history)

v2.1 layout:
  devref/
  ├── devref.py               (entry point — arg dispatch table)
  ├── devref.bat              (Windows launcher)
  ├── commands/               (one file per CLI command)
  │   ├── cmd_find.py
  │   ├── cmd_search.py
  │   ├── cmd_new.py
  │   ├── cmd_add.py
  │   ├── cmd_edit.py
  │   ├── cmd_del.py
  │   ├── cmd_list.py
  │   ├── cmd_export.py
  │   ├── cmd_import.py
  │   ├── cmd_prompt.py
  │   └── cmd_note.py
  ├── components/             (shared UI and input helpers)
  │   ├── display.py
  │   ├── editor.py
  │   └── wizard.py
  ├── utils/                  (data layer)
  │   ├── fs.py
  │   ├── header.py
  │   └── ids.py
  ├── src/
  │   └── header.json         (master index, replaces tools.json)
  ├── ref/
  │   ├── git.json            (one file per tool)
  │   ├── python.json
  │   └── ...
  └── notes/
      └── *.txt               (note files, new in v2.1)

Reason: Splitting tools into individual files avoids loading the entire
database for every command and keeps each tool's data self-contained and
portable. Commands, UI components, and data utilities are separated into
their own modules instead of living in a single script.

header.json structure:
  {
    "tools": ["git", "python"],
    "git": {
      "id":          "A3F9C1",
      "name":        "git",
      "type":        "cmdlinetool",
      "tags":        [...],
      "description": "...",
      "topics":      ["commit", "branch"]
    }
  }

ref/<tool>.json structure:
  {
    "id":   "A3F9C1",
    "name": "git",
    "topics": {
      "commit": {
        "name":         "commit",
        "type":         "subcommand",
        "tags":         [...],
        "description":  "...",
        "what_it_does": "...",
        "use_cases":    [...],
        "syntax":       [...],
        "examples":     [...],
        "flags":        { "--flag": "description", ... },
        "arguments":    { "<arg>": "description", ... }
      }
    }
  }


----------------------------------------------------------
  CODEBASE STRUCTURE  (new)
----------------------------------------------------------

v2.0: single devref.py script.

v2.1: split into four packages:

  commands/   one module per CLI flag (cmd_find, cmd_new, etc.)
  components/ shared terminal output, editor, and wizard helpers
  utils/      filesystem, header CRUD, ID generation, normalisation

devref.py is now a thin dispatch table only — no logic lives there.

Key modules:

  utils/fs.py       load_json / save_json, path constants
  utils/ids.py      generate_hex_id, normalise, fuzzy_name_match
  utils/header.py   load/save header and ref files, resolve_tool,
                    find_tool_keys, add_tool_to_header
  components/display.py   all terminal output (supports colorama)
  components/wizard.py    ask / ask_list / ask_flags / collect_topic_data
  components/editor.py    open_console_editor / open_console_editor_json


----------------------------------------------------------
  TOOL NAME MATCHING  (improved)
----------------------------------------------------------

v2.0: exact lowercase match only. "git" ≠ "Git".

v2.1: all names are normalised by stripping spaces, underscores, and
hyphens and lowercasing before comparison. Implemented in utils/ids.py.

  git  ==  Git  ==  G_it  ==  g-it  ==  GIT

Multi-word names are joined automatically:
  "hello world" is stored and looked up as "helloworld".
  devref --find hello world
  → no quotes needed, joins to "helloworld"

When two distinct keys normalise to the same string, both are shown with
their hex IDs and the user selects by ID:
  devref --find git --id A3F9C1


----------------------------------------------------------
  HEX IDs  (new)
----------------------------------------------------------

Every tool now has a 6-digit uppercase hexadecimal ID, auto-generated at
creation time by generate_hex_id() in utils/ids.py.

  Example: A3F9C1

IDs are displayed in --list and when multiple tools match the same
normalised name. Case-insensitive: A3F9C1 == a3f9c1.

Used for disambiguation only; normal lookup is by name.


----------------------------------------------------------
  TYPE FIELD  (new)
----------------------------------------------------------

v2.0: no type classification for tools or topics.

v2.1: a "type" field has been added at both the tool level and the topic
level.

Tool-level type (stored in header.json):
  interpreter    runtime that executes code (Python, Node)
  cmdlinetool    standalone CLI binary (git, curl, jq)
  framework      application framework (Django, React)
  library        importable code library
  builtin        shell built-in or OS primitive
  packagemanager package/dependency manager (pip, npm)

Topic-level type (stored in ref/<tool>.json):
  subcommand     a named subcommand (git commit, docker run)
  flag           a specific flag or option (--verbose)
  concept        a mental model or idea (branching strategy)
  workflow       a multi-step process (release flow)

The type is shown in --find output and included in AI prompt templates
so generated JSON matches the schema.


----------------------------------------------------------
  FLAGS AND ARGUMENTS FIELDS  (new)
----------------------------------------------------------

v2.0: no structured field for flags or positional arguments.

v2.1: two optional fields added to the topic schema:

  "flags": {
    "--amend":      "rewrite the previous commit",
    "--no-edit":    "keep the existing commit message",
    "-m <message>": "set commit message inline"
  }

  "arguments": {
    "<message>": "the commit message string"
  }

flags is a { "--flag": "description" } map. Keys use the actual flag
string including any arg placeholder. arguments is a { "<arg>": "desc" }
map for positional arguments in angle-bracket notation.

Both fields are optional — omit them if the topic has no flags or
positional args. They are rendered as key→description tables by
display_topic() and included in all AI prompt and notepad templates.


----------------------------------------------------------
  SNIPPETS  (removed)
----------------------------------------------------------

The entire snippets system has been removed:
  - snippets.json file
  - devref --find <tool> --snippets
  - devref --find <tool> --snippets <name>
  - devref --add <tool> --snippets
  - devref --add <tool> --snippets --notepad
  - devref --delete <tool> --snippets <name>
  - devref --edit <tool> --snippets <name>

Reason: snippets and topics covered overlapping ground. Everything is now
unified under topics.


----------------------------------------------------------
  SEARCH  (redesigned)
----------------------------------------------------------

v2.0: free-text fuzzy search across all content in all files.
  devref --search "environment"
  → matched words anywhere in descriptions, examples, etc.

v2.1: tag-based search only.
  devref --search <tag>
  → searches tool-level and topic-level tags across all tools

  devref --find <tool> --tag <tag>
  → searches topic-level tags within one tool

All free-text / fuzzy / word-in-description search has been removed. This
includes all --search sub-flags:
  --tools, --snippets, --topics, --usecases, --examples
  (these flags no longer exist)

Also removed:
  devref --find <tool> --search "<text>"
  devref --find <tool> --search "<text>" --topics
  devref --find <tool> --search "<text>" --snippets
  devref --find <tool> --search "<text>" --usecases
  devref --find <tool> --search "<text>" --examples


----------------------------------------------------------
  --new  (changed)
----------------------------------------------------------

v2.0: wizard asked for description, use-cases, tags then opened a loop for
topics. --notepad opened Windows Notepad.

v2.1: same terminal wizard behaviour. Now also prompts for tool-level type
(via collect_tool_type() in wizard.py).
--notepad now opens the system console editor ($EDITOR / nano / vim / vi /
notepad.exe) instead of Windows Notepad only. Template includes type,
flags, and arguments placeholders matching the new schema.

Use cases at the tool level have been removed from the wizard (they are
still supported in topic entries).


----------------------------------------------------------
  --add  (changed)
----------------------------------------------------------

v2.0: devref --add <tool> --topic     (no topic name, prompted)
      devref --add <tool> --snippets  (snippets variant)

v2.1: devref --add <tool> --topic <name>
      Topic name is supplied on the command line.
      --snippets variant removed entirely.
      Wizard now collects type, flags, and arguments in addition to the
      previous fields.
      --notepad opens console editor instead of Windows Notepad.

inner_call mode: cmd_add accepts inner_call=1 which bypasses the
interactive wizard and writes an empty skeleton. Used internally by
cmd_find --prompt to silently pre-create a topic before generating a
prompt.


----------------------------------------------------------
  --edit  (redesigned)
----------------------------------------------------------

v2.0: devref --edit <tool> --topic <name>
      Showed truncated current value in brackets, asked to retype the full
      field to replace it. No visual editing.

v2.1: devref --edit <tool>
      Opens an editor with name, description and tags pre-loaded. Edit
      only what needs changing. Save and close to apply.

      devref --edit <tool> --topic <name>
      Opens the full topic JSON (including type, flags, arguments) pre-loaded
      in the console editor. All fields visible; edit surgically.

Removed:
  devref --edit <tool> --snippets <name>


----------------------------------------------------------
  --delete  →  --del  (renamed + simplified)
----------------------------------------------------------

v2.0: --delete <tool>
      --delete <tool> --topic <name>
      --delete <tool> --snippets <name>

v2.1: --del <tool>                       (renamed from --delete)
      --del <tool> --topic <name>
      --snippets variant removed.


----------------------------------------------------------
  --prompt  (redesigned)
----------------------------------------------------------

v2.0: devref --prompt <tool>
      devref --prompt <tool> --tools
      devref --prompt <tool> --snippets
      Generated separate prompts for tools.json and snippets.json.

v2.1: devref --prompt <tool>
      Generates a single prompt for the unified tool format. The prompt
      explicitly instructs the AI to include type at the tool level and
      type, flags, and arguments inside each topic. Multiple topics may be
      included in one JSON file.

      devref --find <tool> --prompt <topic>
      New: generates a prompt scoped to one topic, pre-loading current
      topic data so the AI can improve it. If the topic does not exist it
      is auto-created as an empty skeleton first (inner_call=1). Also hints
      that additional related topics may be included in the response.

Removed:
  --prompt <tool> --tools
  --prompt <tool> --snippets


----------------------------------------------------------
  --import  (expanded)
----------------------------------------------------------

v2.0: devref --import <file>
      Auto-detected tools.json vs snippets.json by structure.

v2.1: devref --import <file>
      Imports a file exported by --export (unified format).

      devref --import <file> --tool <name>
      Imports the file as a tool with an explicit name. Merges topics if
      tool already exists.

      devref --import <file> --tool <name> --topic
      Reads <file> as a topic map and adds its entries as topics under the
      named tool. Accepts a plain topic map or a full tool export (id,
      name, description, tags, type keys are skipped automatically).

Import is idempotent — re-importing an updated export merges topics rather
than overwriting.

The snippets.json auto-detection logic has been removed.


----------------------------------------------------------
  --export  (changed format)
----------------------------------------------------------

v2.0: exported as Markdown (.md) file.

v2.1: exports as a single self-contained JSON file (<tool>_export.json)
matching the unified ref format, including the new type, flags, and
arguments fields. This file can be directly re-imported with --import.


----------------------------------------------------------
  --list  (updated output)
----------------------------------------------------------

v2.0: showed ID, name, description, topic count.

v2.1: also shows the tool-level type field alongside the other columns.


----------------------------------------------------------
  --set  (removed)
----------------------------------------------------------

Removed entirely:
  devref --set hints on/off
  devref --set autocomplete on/off
  devref --set  (show settings)

Reason: hints and autocomplete were tied to prompt_toolkit which is no
longer a dependency. Console editor replaces the wizard for complex edits.


----------------------------------------------------------
  --recent  (removed)
----------------------------------------------------------

devref --recent  has been removed. Lookup history is no longer tracked.


----------------------------------------------------------
  --backup  (removed)
----------------------------------------------------------

devref --backup  has been removed. Since each tool is its own file,
version control (git) or manual file copies are a better fit.


----------------------------------------------------------
  --note  (new)
----------------------------------------------------------

A new command for personal scratch notes:

  devref --note
      List all notes with last-modified timestamps.

  devref --note <name>
      Open or create a note in the console editor. On creation, a header
      comment is inserted. On every save, a  # Last saved: <timestamp>
      line is appended to the file automatically.

  devref --note <name> --del
      Delete the note (requires typing name to confirm).

Notes are stored as plain .txt files in notes/.


----------------------------------------------------------
  --tag  command  (removed)
----------------------------------------------------------

v2.0: devref --tag <tool> <topic> "<tag>"
      A dedicated command to add a tag to a topic.

v2.1: Tags are managed via --edit <tool> --topic <name>, which opens the
full topic JSON. Add or remove tags there. The standalone --tag command
has been removed.


----------------------------------------------------------
  --find --tag  (simplified)
----------------------------------------------------------

v2.0: devref --find --tag "<tag>"  (no tool specified)

v2.1: devref --find <tool> --tag <tag>  (scoped to a tool)
      devref --search <tag>             (cross-tool tag search)

The old  devref --find --tag  form without a tool name is replaced by
devref --search <tag>.


----------------------------------------------------------
  DEPENDENCIES  (simplified)
----------------------------------------------------------

Removed optional dependencies:
  rapidfuzz       (used for fuzzy free-text search — removed)
  prompt_toolkit  (used for autocomplete wizard — removed)

Remaining optional:
  colorama        (colour output on Windows; graceful fallback)

devref v2.1 runs on the Python standard library alone. No pip install
required for core functionality.
